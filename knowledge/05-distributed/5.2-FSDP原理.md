# 5.2 FSDP 原理：shard 参数/梯度/优化器，all_gather / reduce_scatter

## 一句话
FSDP（Fully Sharded Data Parallel）= ZeRO-3 的 PyTorch 实现：把**参数、梯度、优化器状态全部按卡切分**，每层计算前临时 all-gather 出完整参数、算完即释放——用通信换显存，让多卡能训远超单卡的模型。

## 核心公式/原理

### ZeRO 的三级切分（理解 FSDP 的钥匙）
朴素 DP 每卡存全量"参数+梯度+优化器"（共 $16P$，[[1.5-显存分配精算]]）。ZeRO 逐级切分：

| 级别 | 切分对象 | 每卡显存（$N$ 卡） | 说明 |
|---|---|---|---|
| ZeRO-1 | 优化器状态 | $4P + 4P + 8P/N$ | 优化器(8P)切 N 份 |
| ZeRO-2 | + 梯度 | $4P + 2P/N + 8P/N$ | 梯度也切 |
| **ZeRO-3 = FSDP** | **+ 参数** | **$(2P+2P+4P+8P)/N = 16P/N$** | 全切 |

> [!important] FSDP 每卡显存
> $$\text{每卡训练态} = \frac{16P}{N}$$
> 这正是 [[1.5-显存分配精算]] 里"8 卡 FSDP 训 8B ≈16.4GB/卡"的来源。$N$ 越大每卡越省，但通信越频繁。

### FSDP 的一次前向/反向（数据流）
FSDP 把模型按层包成若干 unit，每个 unit 的参数平时**切分存放**，用时才聚合：

```
前向到某层:
  ① all-gather:  把该层切片的参数从各卡聚合 → 完整权重
  ② 用完整权重算前向
  ③ 立即释放完整权重（只留切片）→ 省显存
反向到某层:
  ① all-gather 该层完整权重（再次聚合）
  ② 算梯度
  ③ reduce-scatter: 梯度求和并切回 N 份（每卡只留自己那片的梯度）
```

> [!note] 两个关键集合通信
> - **all-gather**：各卡把各自切片拼成完整张量（前向/反向取权重时用）。
> - **reduce-scatter**：先 reduce（求和）再 scatter（切回），反向归并梯度时用。
> 两者通信量都 ≈ 参数量，但发生在层粒度，可与计算重叠（prefetch）。

### 通信与计算重叠（性能关键）
- **forward prefetch**：算第 $i$ 层时，提前 all-gather 第 $i+1$ 层权重 → 通信藏在计算下。
- verl 支持 FSDP forward prefetch（见 [[7.1-性能调优]]）。

### FSDP 的 offload（与 [[1.5-显存分配精算]] 呼应）
| 配置 | 作用 |
|---|---|
| `fsdp_config.param_offload` | 参数切片卸 CPU，用时取回 |
| `fsdp_config.optimizer_offload` | 优化器状态卸 CPU |
| `fsdp_config.fsdp_size` | 分片组大小（可小于总卡数，做混合分片） |

> [!warning] FSDP 不是免费的
> 显存省到 $16P/N$，代价是每层 all-gather/reduce-scatter 的通信。卡数 $N$ 翻倍，通信也翻倍，到一定程度通信会吃掉算力（强扩展瓶颈）。所以 FSDP 适合"单卡装不下"的场景，不是卡越多越好。

### FSDP vs Megatron（先给结论，详见 [[5.3-Megatron原理]]）
| | FSDP | Megatron |
|---|---|---|
| 切分哲学 | 数据并行 + 参数分片（ZeRO-3） | 模型并行（TP/PP/SP） |
| 通信 | 层粒度 all-gather | TP 每层 all-reduce（更频繁） |
| 易用性 | 高（HF 模型直接包） | 需模型改写适配 |
| 适合 | 快速上手、中等规模 | 超大模型、极致性能 |
