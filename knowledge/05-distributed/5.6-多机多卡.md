# 5.6 多机多卡：nnode、Ray 集群、NCCL、故障排查

## 一句话
单机 8 卡装不下或不够快时，就上多机：用 Ray 把多台机器的 GPU 组成一个集群，NN 间靠 NCCL/网络通信；多机的关键是"Ray 集群怎么起、跨机通信怎么调、故障怎么查"。

## 核心公式/原理

### verl 多机的两个关键参数
```yaml
trainer.nnodes: 4              # 机器数
trainer.n_gpus_per_node: 8     # 每台机器的 GPU 数
# world_size = nnodes × n_gpus_per_node = 32
```
- `world_size` 决定 FSDP 分片度（[[5.5-分布式显存重分配]]）与 rollout 副本编排（[[5.4-verl并行映射]]）。
- 多机时这些整除约束仍要满足：world_size 整除 batch、world_size % rollout_tp == 0。

### Ray 集群搭建（多机前置）
```bash
# 头节点（node-0）
ray start --head --node-ip-address=<HEAD_IP> --port=6379

# 每个工作节点
ray start --address=<HEAD_IP>:6379

# 验证
ray status   # 应看到所有节点的 GPU 资源
```

> [!warning] main_task 别放 head
> [[3.1-单控制器架构]] 强调：`main_task`（控制进程）吃内存大，别调度到资源少的 head 节点。多机时这点更重要——head 还要管集群元数据。

### 多机并行的切法选择
跨机网络带宽（IB/RoCE ≈100–400Gbps）远小于单机 NVLink（≈600–900GB/s），所以：

| 并行 | 跨机建议 | 原因 |
|---|---|---|
| **TP** | ❌ 尽量限制在单机内 | 每层 all-reduce，吃高带宽，跨机会严重拖慢 |
| **PP** | ✅ 适合跨机 | 仅层间 p2p 传激活，量小 |
| **FSDP/DP** | ✅ 适合跨机 | 梯度/参数分片通信，可与计算重叠 |
| **SP/CP** | ⚠️ 谨慎 | all-to-all/ring 通信量大 |

> [!tip] 多机黄金搭配
> **单机内 TP（若用 Megatron） + 跨机 FSDP/PP/DP**。例：4 机 × 8 卡，Megatron TP=8（单机内）× PP=2 × DP=2；或纯 FSDP（world_size=32）。TP 绝不跨机。

### NCCL 关键环境变量（多机调优/排障）
```bash
export NCCL_DEBUG=INFO                 # 打印 NCCL 初始化，排查连接问题
export NCCL_IB_GID_INDEX=3             # InfiniBand/RoCE 选对 GID
export NCCL_SOCKET_IFNAME=eth0         # 指定网卡（多网卡时必设）
export NCCL_IB_HCA=mlx5_0,mlx5_1       # 指定 IB 设备
export NCCL_NET_GDR_LEVEL=2            # GPUDirect RDMA 级别
```

### 多机故障排查清单
| 症状 | 可能原因 | 排查 |
|---|---|---|
| 卡在 NCCL init | 网卡/防火墙/GID 错 | 看 NCCL_DEBUG=INFO 日志，确认节点互通 |
| 某节点看不到 GPU | Ray 没起对 / CUDA_VISIBLE_DEVICES | `ray status` + 节点上 `nvidia-smi` |
| 速度远低预期 | TP 跨机 / 网络拥塞 / GDR 没开 | 确认 TP 在单机内、查 NCCL_NET_GDR_LEVEL |
| 随机 hang | 共享内存不足 / 版本不齐 | 各机 `--shm-size`、统一镜像版本 |
| OOM 只在多机出现 | world_size 变了但 batch 没重算 | 重算 [[3.5-batch体系]] + [[5.5-分布式显存重分配]] |

> [!danger] 多机最常见的隐性坑
> 从单机改多机时，`world_size` 变了，但 `train_batch_size`/`rollout.n`/`mini_batch` 没跟着调 → 要么整除报错，要么每卡显存算错。改 nnode/n_gpus 后**必须重跑 batch 整除检查和多卡显存精算**。

### 多机显存/通信权衡
- 卡数从 8→32，每卡训练态 $16P/N$ 从 16.4→4.1 GB（8B），显存大幅宽松 → 可加大 batch 或关 offload 提速。
- 但跨机通信增加 → 要确认网络（IB/RoCE + GDR）够用，否则算力空转。
- rollout：vLLM 副本数 = world_size/tp 变多，吞吐提升，但要管好跨机的请求分发。
