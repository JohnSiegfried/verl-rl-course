# 2.6 PPO vs GRPO vs DAPO vs REINFORCE++ 对比

## 一句话
这些算法都是策略梯度的变体，差异集中在"优势怎么估、要不要 critic、KL 放哪、clip 怎么调"；选对算法主要看任务类型（有无标准答案）、显存预算与稳定性要求。

## 核心公式/原理

### 总览对比表
| 维度 | PPO | GRPO | DAPO | REINFORCE++ |
|---|---|---|---|---|
| **critic 网络** | ✅ 需要 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 |
| **优势估计** | GAE（逐 token） | 组内 z-score | 组内 z-score（改进） | 组内/批次基线 |
| **显存** | 高（多 critic） | **低** | 低 | 低 |
| **KL 处理** | 常进 reward | 作 loss 项 | 作 loss 项 | 作 loss 项 |
| **clip** | 单侧 0.2 | 单侧 0.2 | **双侧 clip-higher** | 标准 |
| **典型场景** | 通用 RLHF | **数学/代码 RLVR** | 长链推理 RLVR | 轻量 baseline |
| **verl 配置** | `adv_estimator=gae` | `adv_estimator=grpo` | `adv_estimator=grpo`+DAPO 配方 | `adv_estimator=reinforce_plus_plus` |

### PPO：通用但带 critic 的负担
- 优势靠 GAE + critic， critic 本身要训练、占显存、可能不准。
- 适合：开放式 RLHF（无标准答案，靠 RM 打分），需要逐 token 细粒度优势。
- verl 里要额外配 `critic` 模型 + `trainer.critic_warmup`。

### GRPO：推理任务的显存友好之选
- 组内相对优势免 critic，显存省一大块（[[1.5-显存分配精算]]）。
- 适合：有标准答案/可验证奖励的任务（数学、代码），DeepSeek-R1、Qwen3-Thinking 都用它。
- 必须 `rollout.n > 1`（组内对比），见 [[2.4-优势估计]]。

### DAPO：GRPO 的长链推理改进版
DAPO（Decoupled Clip and Dynamic sAmpling Policy Optimization）针对 GRPO 在长 CoT 上的几个问题做了改进：

| DAPO 改进 | 解决的问题 | 说明 |
|---|---|---|
| **Clip-Higher** | 熵坍缩 | 把 clip 上下界解耦（$\epsilon_{low}, \epsilon_{high}$），提高上限鼓励探索，防熵过早坍缩 |
| **Dynamic Sampling** | 有效梯度少 | 过滤"全对/全错"的组（这些组优势全 0，无梯度），只留信息量在的组，提高样本效率 |
| **Token-Level Loss** | 长度偏置 | 用 token 级聚合（对应 verl `token-mean`），避免长序列被欠权 |
| **Overlong Reward Shaping** | 截断惩罚失真 | 对超长被截断的 response 给软惩罚而非硬 0 分，减少奖励噪声 |

> [!tip] DAPO 在 verl 中的落地
> verl 用 `adv_estimator=grpo` + DAPO 配方（recipe 子模块）实现，配合 `dapo` reward manager（含 overlong penalty）。`loss_agg_mode=token-mean` 正是 DAPO 的 Token-Level Loss 思想。
> 来源：verl DAPO 训练实验记录 + DAPO 论文（见关键来源）。

### REINFORCE++：轻量基线
- 在 REINFORCE 基础上加 PPO 的 clip 与 KL 正则，但仍用批次/组内基线（无 critic）。
- 适合：想要比 GRPO 更简单的 baseline，或样本量不大时。

### 怎么选（决策树）
```
任务有标准答案/可验证奖励（数学/代码/推理）?
├─ 是 → 显存紧张 or 长链推理?
│        ├─ 长链/追求SOTA → DAPO
│        └─ 常规 → GRPO ✅（本课程主线）
└─ 否（开放式对话/偏好对齐，靠 RM）
         → 有 RM 且要细粒度优势 → PPO（带 critic）
         → 想要简单 → REINFORCE++
```

> [!important] 本课程为什么以 GRPO 为主线
> ① 企业后训练当前最高频需求是数学/代码/推理（RLVR），正是 GRPO/DAPO 的主场；② GRPO 免 critic，显存友好，适合双档（小资源+集群）教学；③ 它是理解 PPO/DAPO 的最佳中间点——学会 GRPO，向上学 DAPO 改进、向下理解 PPO 的 critic 都顺理成章。
