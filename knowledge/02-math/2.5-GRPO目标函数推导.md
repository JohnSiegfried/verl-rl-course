# 2.5 GRPO 目标函数完整推导 + loss_agg_mode

## 一句话
GRPO = PPO 的 clip 框架 + 组内相对优势（替代 critic）+ KL 正则项；把 [[2.2-重要性采样与PPO-clip]]、[[2.3-KL正则]]、[[2.4-优势估计]] 三块拼起来就是完整目标。

## 核心公式/原理

### GRPO 完整目标函数
对每个 prompt $x$，从旧策略 $\pi_{\theta_{old}}$ 采样一组 $G$ 个 response $\{y_1,\dots,y_G\}$，GRPO 最大化：

$$\mathcal{J}_{GRPO}(\theta) = \mathbb{E}_{x}\frac{1}{G}\sum_{i=1}^{G}\Bigg[\underbrace{\frac{1}{|y_i|}\sum_{t=1}^{|y_i|}\min\Big(r_{i,t}\hat{A}_i,\ \text{clip}(r_{i,t},1{-}\epsilon,1{+}\epsilon)\hat{A}_i\Big)}_{\text{① PPO clip 项（token 级）}} - \underbrace{\beta\,\mathbb{D}_{KL}(\pi_\theta\|\pi_{ref})}_{\text{② KL 正则}}\Bigg]$$

其中：
- $r_{i,t} = \dfrac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{\theta_{old}}(y_{i,t}|x,y_{i,<t})}$ — 逐 token 概率比
- $\hat{A}_i = \dfrac{R_i - \text{mean}(\{R_j\})}{\text{std}(\{R_j\})}$ — 组内相对优势（序列级，$R_i$ 为第 $i$ 条的总 reward）
- $\beta$ = `kl_loss_coef`，$\epsilon$ = `clip_ratio`

> [!important] GRPO 与 PPO 的三处本质差异
> 1. **优势来源**：PPO 用 critic 算 GAE（逐 token）；GRPO 用组内 z-score（序列级，所有 token 共享同一 $\hat{A}_i$）。
> 2. **没有 critic / value loss**：GRPO 目标里没有 $\mathcal{L}^{VF}$，省掉 critic 网络。
> 3. **KL 位置**：PPO 常把 KL 加进 reward；GRPO 把 KL 作为独立项（`-β·KL`）放进目标，`use_kl_loss=True`、`use_kl_in_reward=False`。

### loss_agg_mode：怎么聚合 token 级 loss
一个 batch 里有长有短的 response，token 数不同，如何把所有 token 的 clip loss 聚成一个标量？verl 的 `actor_rollout_ref.actor.loss_agg_mode` 提供三种：

| 模式 | 聚合方式 | 含义与适用 |
|---|---|---|
| **token-mean** | 所有 token 的 loss 直接求均值 | 每个 token 等权。verl 示例默认，**token 级更稳**，长序列不会主导 |
| **seq-mean-token-sum** | 每条序列内 token 求和，再对序列求均值 | 每条序列等权，长序列贡献大 |
| **seq-mean-token-mean** | 每条序列内 token 求均值，再对序列求均值 | 每条序列等权且归一。**原始 GRPO 论文的聚合**，长 CoT 场景可能更不稳 |

> [!tip] 怎么选
> - 工程默认 **token-mean**（verl 官方示例用它，token 级聚合更稳）。
> - 想严格复现 GRPO 论文 → `seq-mean-token-mean`（样本级聚合）。
> - 长链推理（long CoT）注意：seq 级聚合会让短序列梯度被放大，可能不稳，优先 token-mean。
> 来源：verl 框架源码分析（loss_agg_mode 三种模式说明）。

### GRPO 训练伪代码（对应 verl 数据流）
```python
for batch_prompts in dataloader:                    # train_batch_size 个 prompt
    # ① Rollout：每个 prompt 采 n 个 response（rollout.n = G）
    responses = actor_rollout.generate(batch_prompts, n=G)      # vLLM
    # ② 算 log 概率
    old_logp  = actor.compute_log_prob(responses)   # 采样时冻结
    ref_logp  = ref.compute_ref_log_prob(responses) # 参考模型（KL 用）
    # ③ 算 reward（规则 / RM）
    R = reward_fn(responses)                         # 每条一个标量
    # ④ 组内相对优势
    A = (R - mean_per_group(R)) / std_per_group(R)   # ← GRPO 核心
    # ⑤ PPO 内循环：多个 epoch + mini-batch
    for epoch in range(ppo_epochs):
        for mb in split(responses, ppo_mini_batch_size):
            cur_logp = actor.compute_log_prob(mb)    # 当前策略
            ratio = exp(cur_logp - old_logp)         # ← 2.2 的 ratio
            clip_loss = min(ratio*A, clip(ratio,1±ε)*A)
            kl = low_var_kl(cur_logp, ref_logp)      # ← 2.3 的 k3
            loss = -agg(clip_loss, mode=loss_agg_mode) + β*kl
            loss.backward(); optimizer.step()
```
> 每一步与 [[3.4-数据流转全链路]] 的 DataProto 字段一一对应。
