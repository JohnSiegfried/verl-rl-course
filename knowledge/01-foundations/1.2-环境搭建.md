# 1.2 环境搭建：Docker 镜像、verl 安装、依赖

## 一句话
verl 强耦合 CUDA / PyTorch / vLLM / flash-attn 等底层库，**强烈推荐用官方预编译 Docker 镜像**而不是从零 pip 安装，可避免 90% 的版本地狱。verl 的一步 GRPO 训练需要什么：

```
一次训练步内：
  ├── PyTorch 做反向传播（训练 actor）
  ├── vLLM 做高吞吐采样（rollout 生成 response）
  ├── flash-attn 做高效注意力计算（长序列必备）
  └── Ray 调度多进程（单控制器 → 多 Worker）
```

这四个库对 CUDA 版本、编译 ABI（`libstdc++` 的 CXX11 还是 pre-CXX11）、算子实现（flash-attn 的 CUDA kernel）有**严格一致性要求**。

举个例子：本机的 PyTorch 是 CUDA 11.8 编译的，但 vLLM 需要 CUDA 12.4+——装不上，跑不了。这就是所谓的"版本地狱"。

## 核心公式/原理

### 推荐路径：官方 Docker 镜像
verl 社区提供了把 PyTorch + vLLM + flash-attn + apex 等依赖打包好的 NGC 风格镜像。一个被社区验证可跑通 Qwen3-8B GRPO 的镜像示例：

```bash
hiyouga/verl:ngc-th2.6.0-cu126-vllm0.8.4-flashinfer0.2.2-cxx11abi0
```

> [!success] 为什么用镜像
> verl 需要 `torch`、`vllm`（或 sglang）、`flash-attn`、`transformer-engine`、`apex`（Megatron 后端时）等精确匹配的版本。手动编译 flash-attn / apex 在新 CUDA 上极易失败。镜像已对齐 ABI 与算子，开箱即用。
> 来源：verl 社区 GRPO 示例脚本头部注释（见关键来源）。

### 启动容器（单机 8 卡示例）
```bash
docker run --gpus all --ipc=host --shm-size=64g \
  -v $PWD:/workspace -w /workspace \
  -it hiyouga/verl:ngc-th2.6.0-cu126-vllm0.8.4-flashinfer0.2.2-cxx11abi0 bash
```
- `--ipc=host` + `--shm-size`：NCCL / 多进程通信需要足够共享内存，不足会挂死。
- `--gpus all`：暴露全部 GPU。

### 源码安装 verl（镜像内）
```bash
git clone https://github.com/verl-project/verl.git
cd verl
pip install -e .
```
- `-e`（editable）：方便改源码（本课程多处需要读/改 verl 源码）。
- `recipe/` 是 git 子模块（算法配方仓库），需要时 `git submodule update --init`。

### 依赖分工一览
| 依赖                                              | 作用                 | 何时需要           |
| ----------------------------------------------- | ------------------ | -------------- |
| `torch`                                         | 训练后端基础             | 总是             |
| `vllm` 或 `sglang`                               | **Rollout**（高吞吐采样） | 生成 response 阶段 |
| `flash-attn`                                    | 高效注意力算子            | 训练 + 长序列       |
| `fsdp`（torch 内置）                                | 训练并行后端之一           | FSDP 方案        |
| `megatron-core` + `apex` + `transformer-engine` | 训练并行后端之二           | Megatron 方案    |
| `ray`                                           | 单控制器多进程调度          | 总是             |
| `liger-kernel`                                  | 算子融合省显存提速          | 可选优化           |
| `wandb` / `mlflow`                              | 训练指标记录             | 观测（Phase 6/7）  |

|         阶段         |          谁在工作           |                       依赖                        |
| :----------------: | :---------------------: | :---------------------------------------------: |
|    Rollout（采样）     |       vLLM/SGLang       |           `vllm`, `flash-attn`, CUDA            |
|   log_prob（算概率）    | PyTorch + FSDP/Megatron |              `torch`, `flash-attn`              |
| ref_log_prob（参考模型） |     PyTorch + FSDP      |                      torch                      |
|     reward（打分）     |        纯 Python         |                      无特殊依赖                      |
|    update（反向更新）    | PyTorch + FSDP/Megatron | `torch`, `flash-attn`, `transformer-engine`(可选) |
|       全流程调度        |           Ray           |                       ray                       |
每一个依赖只在特定阶段起作用。这意味着：
如果你的 rollout 一直不跑，查 vLLM 版本
如果你的 update 一直 OOM，查 FSDP 配置 + flash-attn 版本
如果 Ray Actor 起不来，查 --shm-size 是否够大
> [!warning] vLLM 版本要新
> verl 官方建议 vLLM ≥ v0.8.3，并针对 v0.8 写了专门适配说明（`docs/README_vllm0.8.md`）。旧版 vLLM 的 `gpu_memory_utilization` 语义不同，会导致显存估算偏差。

### 验证安装
```python
import torch, vllm, verl
print(torch.__version__, torch.cuda.is_available())
print(vllm.__version__)
print(verl.__version__)
```

## 与其他概念的关系
- **前置依赖**：Docker、NVIDIA 驱动、nvidia-container-toolkit 基础。
- **对比区别**：FSDP 后端只需 torch，Megatron 后端额外需要 apex + transformer-engine + megatron-core。
- **后续延伸**：[[4.2-小资源版脚本]]、[[4.3-集群版脚本]]（在镜像内启动训练）、[[1.5-显存分配精算]]（镜像内各组件的显存占用）。
- 如果你的服务器上没有 Docker，也有备选方案——conda/pip 手动装。思路是"先大后小"：

```bash
# 步骤 1：创建 conda 环境
conda create -n verl python=3.10 -y

# 步骤 2：先装 PyTorch（指定 CUDA 版本）
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124

# 步骤 3：vLLM（这一步最复杂，版本必须跟 CUDA 对齐）
pip install vllm>=0.8.3

# 步骤 4：flash-attn
pip install flash-attn --no-build-isolation

# 步骤 5：verl（editable）
git clone https://github.com/verl-project/verl.git
cd verl && pip install -e .
```

> **警告**：步骤 3 和 4 是最高频的失败点。`flash-attn` 在无 GPU 节点上编译会直接报错，vLLM 的 CUDA 版本匹配也极易出错。这就是为什么笔记里说"强烈推荐 Docker"。
