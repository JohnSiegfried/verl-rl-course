# 1.6 选模型 + 选显卡实战：从显存反推配置，避免 OOM

## 一句话
给定你的显卡（显存大小与卡数），用 [[1.5-显存分配精算]] 的公式**反推**能训的模型、并行方式与开关组合，在跑之前就确保不 OOM。

## 核心公式/原理

### 决策流程（自上而下）
```
显卡显存 M 与卡数 N
   │
   ▼
① 单卡能否装下 actor 训练态 16P/N ?
   ├─ 否 → 降模型 / 加卡 / 开 offload / 用 LoRA
   ▼
② rollout 推理态(2P + KV) 能否与训练态共存 ?
   ├─ 否 → 调低 gpu_memory_utilization / offload actor 参数
   ▼
③ 激活是否过大 ?
   ├─ 是 → gradient checkpointing + remove_padding + 减 micro_batch
   ▼
④ 留 10–20% 余量 → 得最终配置
```

### 手段一：LoRA 大幅降低训练态
全参训练态是 $16P$；LoRA 只训练注入的低秩矩阵（参数量常为全参的 0.1%–1%），训练态显存近似：
$$\text{LoRA 训练态} \approx \underbrace{2P}_{\text{冻结base权重}} + \underbrace{16 \cdot P_{lora}}_{\text{可训参数}}$$
$P_{lora} \ll P$，所以训练态从 $16P$ 降到约 $2P$ + 一点点。

> [!success] LoRA 是小资源的救命稻草
> Qwen3-1.7B 全参训练态 ≈27GB（单卡 4090 装不下）；换 LoRA 后训练态 ≈ $2×1.7$ + 少量 ≈ 4–6GB，单卡 4090 轻松装下，还能给 rollout 留足显存。
> 注意：verl 中 actor 与 reference colocate 的设计，正好支持"ref 就是 LoRA 的 base model"，实现高效 LoRA PPO/GRPO。
> 来源：verl HybridFlow Guide（actor/ref colocate 用于高效 LoRA）。

### 手段二：offload 把训练态卸到 CPU
| 开关 | 作用 | 代价 |
|---|---|---|
| `actor.fsdp_config.param_offload=True` | actor 参数卸 CPU | 取用时 PCIe 传输变慢 |
| `actor.fsdp_config.optimizer_offload=True` | 优化器状态卸 CPU | 更新变慢 |
| `ref.fsdp_config.param_offload=True` | ref 参数卸 CPU | 算 ref_log_prob 变慢 |
| `*.enable_activation_offload=True` | 激活卸 CPU（仅 FSDP） | 配合 gradient ckpt |

> [!warning] offload 省显存但慢
> offload 用时间换空间。小资源（显存不足）时不得不用；大集群（显存充足）时通常 `param_offload=False, optimizer_offload=False` 追求速度。ref 模型几乎总是 offload（用得少）。

### 手段三：缩小 micro-batch + 动态 batch
- `*_micro_batch_size_per_gpu` 直接决定激活大小，是 OOM 时**最先调小**的旋钮。
- `use_dynamic_bsz=True` 按 token 数动态组 batch，长序列不爆显存，吞吐更高。
- 详见 [[3.5-batch体系]]、[[4.5-OOM排查决策树]]。

### 场景决策表（核心交付）

**场景 A：1× RTX 4090 (24GB)**
| 模型 | 方案 | actor 训练态 | rollout | 结论 |
|---|---|---|---|---|
| Qwen3-0.6B | 全参 + offload | 16×0.6≈10GB | g_util 0.5 | ✅ 可行 |
| Qwen3-1.7B | **LoRA** | ≈5GB | g_util 0.5 | ✅ 推荐 |
| Qwen3-1.7B | 全参 | ≈27GB | — | ❌ 装不下 |
| Qwen3-4B | LoRA + offload | ≈10GB | g_util 0.4 | ⚠️ 紧张可行 |

**场景 B：4× A6000 (48GB)**
| 模型 | 方案 | 配置要点 | 结论 |
|---|---|---|---|
| Qwen3-4B | 全参 FSDP/4 | 训练态 16×4/4≈16GB/卡 | ✅ 舒适 |
| Qwen3-8B | 全参 FSDP/4 + offload | 训练态≈33GB/卡 + ckpt | ⚠️ 紧张 |
| Qwen3-8B | LoRA FSDP/4 | 训练态≈4GB/卡 | ✅ 推荐 |

**场景 C：8× A100/H100 (80GB)**
| 模型 | 方案 | 配置要点 | 结论 |
|---|---|---|---|
| Qwen3-8B | 全参 FSDP/8 | 见 [[1.5-显存分配精算]] 预算表 | ✅ 官方示例档 |
| Qwen3-14B | 全参 FSDP/8 + ckpt | 训练态≈29GB/卡 | ⚠️ 需精算 |
| Qwen3-32B | 全参 FSDP/8 + 强 offload | 训练态≈64GB/卡 | ⚠️ 极限，建议多机 |

> [!tip] 经验法则
> - **全参训练**：单卡显存 ≥ $16P/N$ + rollout($2P$+KV) + 激活 + 余量。
> - **显存不够先想 LoRA**：能把训练态从 $16P$ 压到 $2P$ 量级。
> - **rollout 是弹性项**：OOM 先降 `gpu_memory_utilization`，再降 `micro_batch`。
> - **8B 全参的甜区是 8×80GB**；更小模型可在更少/更小卡上跑，更大模型要多机或 LoRA。

```
② rollout = gpu_memory_utilization × 单卡显存 = ____ GB
③ 激活（ckpt? remove_padding? micro_batch=__）≈ ____ GB
④ ref/reward offload？ = ____

```
