# 1.1 RL 后训练全景：SFT → RM → RLHF/RLVR，verl 的定位

## 一句话
大模型后训练是把"预训练得到的通用模型"对齐到"人类偏好/特定任务"的过程，verl 是其中负责**强化学习阶段**（RLHF/RLVR）的高效分布式训练框架。

## 核心公式/原理

### 后训练的四段式流水线
企业级大模型后训练通常包含以下阶段（以 Qwen3 官方流程为参照）：

1. **SFT（Supervised Fine-Tuning，监督微调）**
   用高质量的 (prompt, response) 对做行为克隆，让模型学会"对话/指令格式"。
   损失函数即负对数似然：
   $$\mathcal{L}_{SFT}(\theta) = -\mathbb{E}_{(x,y)\sim \mathcal{D}} \sum_t \log \pi_\theta(y_t \mid x, y_{<t})$$

2. **RM（Reward Model，奖励模型）训练**（仅 RLHF 需要）
   用人类偏好对 $(y_w, y_l)$ 训练一个打分模型 $r_\phi$，常用 Bradley-Terry 损失：
   $$\mathcal{L}_{RM}(\phi) = -\mathbb{E}\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)$$

3. **RL（强化学习）对齐**
   在 RM 或规则奖励信号下，用 PPO/GRPO 等算法优化策略，最大化期望奖励，同时用 KL 正则防止偏离参考模型太远：
   $$\max_\theta \; \mathbb{E}_{y \sim \pi_\theta(\cdot|x)}[r(x,y)] - \beta\, \mathbb{D}_{KL}\big(\pi_\theta \| \pi_{ref}\big)$$

4. **通用 RL / 能力扩展**（可选）
   在指令遵循、格式遵循、Agent 能力等多个领域继续 RL，纠正不良行为。

> [!important] Qwen3 的四阶段后训练
> Qwen3 官方后训练流程为：(1) 长思维链冷启动（SFT）→ (2) 长思维链强化学习（规则奖励 RL）→ (3) 思维模式融合（SFT）→ (4) 通用强化学习（20+ 领域）。其中 (2)(4) 就是 verl 负责的 RL 阶段。
> 来源：见"关键来源"。

### RLHF vs RLVR：奖励从哪来
| 范式 | 全称 | 奖励来源 | 典型任务 |
|---|---|---|---|
| **RLHF** | RL from Human Feedback | 训练好的**奖励模型**（拟合人类偏好） | 开放式对话、有用性/无害性 |
| **RLVR** | RL from Verifiable Rewards | **可验证的规则**（数学答案对错、代码通过测试） | 数学、代码、推理 |

> [!tip] 为什么推理模型（如 Qwen3-Thinking、DeepSeek-R1）偏爱 RLVR
> 数学/代码有"标准答案"，可以写出确定性的 reward function（对/错、pass/fail），不需要训练 RM，避免了 RM 的噪声与 reward hacking。这类任务天然适合 GRPO + 规则奖励。这正是 verl 社区最活跃的方向。

### verl 在这条流水线中的位置
verl（Volcano Engine RL，原 HybridFlow 的官方实现）专注解决 **RL 对齐阶段**的工程难题：

- **多模型协同**：一个 PPO 步需要 actor（生成+更新）、rollout（采样）、reference（算 KL 的冻结模型）、critic（价值估计，GRPO 无）、reward（打分）多个模型在同一张/多张 GPU 上协同。一个 GRPO 训练步需要同时承载：

```
同一张 GPU 上：
  ├── Actor（策略模型，要训练 + 要推理采样）
  ├── Rollout（用 vLLM 快速采样 n 个 response）
  ├── Reference（冻结的基座模型，算 KL 用）
  └── Reward（跑 compute_score）
```
- **训练/推理引擎切换**：训练用 FSDP/Megatron，采样用 vLLM/SGLang，权重需要在两者之间高效 reshard（3D-HybridEngine：训练用 FSDP 切权重，推理用 vLLM 的 TP 切权重。每次切换角色时，"在线"reshard 权重——不存两份。）。
- **单控制器 + 多进程计算**：控制流（RL 算法逻辑）单进程，计算流（模型前向/反向）多进程，解耦后易于换后端、换算法。主进程只跑算法逻辑（控制流），Worker 进程跑模型计算（计算流）。换算法不换架构，换后端不影响算法。

> [!note] verl 不负责什么
> SFT 和 RM 训练不在 verl 主流程内（verl 提供 SFT trainer，但不是重点）。本课程聚焦 RL 阶段；SFT/RM 只讲清与 RL 的接口（数据格式、参考模型）。

## 与其他概念的关系
- **前置依赖**：预训练语言模型基础、Transformer、概率论（期望、KL 散度）。
- **对比区别**：SFT 是"模仿标准答案"，RL 是"在奖励信号下探索更优答案"；RLHF 用学出来的 RM，RLVR 用写死的规则。
- |PPO|GRPO|
  |---|---|
  |**需要 Critic 网络**|✅ 需要（多一个模型占显存）|❌ 不需要|
  |**优势估计**|GAE（需要 Critic 估值）|组内相对优势（z-score）|
  |**显存占用**|Actor + Critic + Ref + Rollout|Actor + Ref + Rollout|
  |**适合场景**|有大量偏好标注数据|可验证的规则奖励|
  GRPO 用"组内对比"替代了 Critic：对同一个 prompt 采样 n 个 response（比如 n=4），算谁的答案更好，优势 = (自己的分 − 组平均分) / 组标准差。**省了一个 Critic 网络，省了显存，省了训 Critic 的复杂度。**
