# 4.4 参数作用精讲：lr / kl / entropy / clip / rollout.n / gpu_mem_util / offload

## 一句话
把 GRPO 脚本里的每个关键参数分成"算法稳定性组 / 数据效率组 / 显存组 / 吞吐组"四类，讲清它控制什么、默认值、何时往大调、何时往小调——这是你从"会跑"到"会调"的核心一课。

## 核心公式/原理

### 一、算法稳定性组（影响"学得稳不稳"）

**`actor_rollout_ref.actor.optim.lr`（学习率，默认 1e-6）**
- 作用：控制每步策略更新幅度。RL 比 SFT 更敏感，lr 通常小一个量级。
- 调大：reward 涨得快但易震荡/KL 爆炸；调小：稳但慢。
- 经验：全参 1e-6 起步；LoRA 可 1e-5；reward 不动先查别的再动 lr。

**`actor_rollout_ref.actor.clip_ratio`（PPO clip，默认 0.2）**
- 作用：[[2.2-重要性采样与PPO-clip]] 的 $\epsilon$，限制 ratio 在 $[1\pm\epsilon]$。
- 调大：允许更大更新（快但险）；调小：更保守（稳但慢）。
- DAPO 用 clip-higher 把上下界解耦（[[2.6-算法对比]]）。

**`actor_rollout_ref.actor.kl_loss_coef`（KL 系数，默认 0.001）**
- 作用：[[2.3-KL正则]] 的 $\beta$，控制"离参考模型多远"。
- 调大：紧贴 ref、reward 涨不动（欠拟合）；调小：易跑偏/reward hacking。
- 经验：数学/代码 0.001–0.01；观测 KL 曲线缓慢上升为佳。

**`actor_rollout_ref.actor.entropy_coeff`（熵系数，默认 0）**
- 作用：给策略熵加奖励，鼓励探索。
- GRPO 默认 0（靠组内对比已够）；熵坍缩（响应趋同）时可给很小正值，或用 DAPO clip-higher。

**`actor_rollout_ref.actor.kl_loss_type`（默认 low_var_kl）**
- k1/k2/k3 估计器，[[2.3-KL正则]]；工程上用 low_var_kl(k3)。

### 二、数据效率组（影响"样本怎么用"）

**`actor_rollout_ref.rollout.n`（每 prompt 采样数，GRPO 必须 >1）**
- 作用：GRPO 组的大小（[[2.4-优势估计]]）。
- 调大：组内对比更充分、优势估计更准，但总 response=train_batch×n 变多（更贵更显存）。
- 经验：数学常用 4–8；显存紧就调小。

**`data.train_batch_size`（全局 prompt 批）**
- 作用：一步用多少 prompt。大→梯度稳、样本多样；小→快、省显存但噪声大。
- 与 rollout.n、world_size 有整除约束（[[3.5-batch体系]]）。

**`actor_rollout_ref.actor.ppo_mini_batch_size`（更新批）**
- 作用：一次 actor 更新用多少 response；决定一步内反向次数。
- `ppo_epochs`（未显式设时默认）控制对同批数据训练几轮。

**采样温度（rollout 的 temperature，默认约 1.0）**
- 作用：控制采样多样性。太低→组内趋同、优势趋 0；太高→质量差。
- 数学任务常 0.7–1.0。

### 三、显存组（影响"会不会 OOM"）

**`rollout.gpu_memory_utilization`（默认经验 0.5–0.7）**
- 作用：vLLM 用单卡显存的比例装权重+KV（[[1.5-显存分配精算]]）。
- OOM 先降它；但要留够 KV，否则 rollout 慢。

**`*_micro_batch_size_per_gpu`（每卡前向/反向序列数）**
- 作用：单卡激活显存的直接旋钮（[[3.5-batch体系]]）。
- OOM 时 32→16→8→4 逐级降；forward-only 的（ref/rollout log_prob）可设大些。

**`enable_gradient_checkpointing`（True/False）**
- 作用：重算换显存，让更大 micro 装得下。代价 +~30% 时间。

**`use_remove_padding` / `use_dynamic_bsz`**
- 作用：去 padding、按 token 动态组 batch，省显存提吞吐。

**offload 系列**
- `actor.fsdp_config.param_offload` / `optimizer_offload`：训练态卸 CPU（省显存变慢）。
- `ref.fsdp_config.param_offload=True`：ref 几乎总是卸（用得少）。
- `enable_activation_offload`：激活卸 CPU（仅 FSDP，配合 ckpt）。

### 四、吞吐组（影响"跑多快"，详见 [[7.1-性能调优]]）
- `rollout.tensor_model_parallel_size`：vLLM TP，小 TP→更多副本→更高 DP 吞吐（但 KV 更多）。
- `max_num_seqs` / `max_num_batched_tokens`：vLLM 解码并发；GPU cache 利用率低就调大（max_num_batched_tokens > 2048）。
- `cudagraph_capture_sizes`：提推理速但显存不可 offload，配大易 OOM。

### 调参速查表
| 症状 | 先动哪个 | 方向 |
|---|---|---|
| 训练 OOM | micro_batch → g_util → offload | 降 / 降 / 开 |
| reward 不涨 | 查 reward 是否正确 → kl_loss_coef → lr | — |
| KL 爆炸 | kl_loss_coef ↑，lr ↓ | — |
| 响应趋同（熵坍缩） | temperature ↑ / clip-higher / entropy_coeff 微增 | — |
| rollout 太慢 | tensor_model_parallel_size ↓、max_num_batched_tokens ↑ | — |
| 长度爆炸 | max_response_length、长度惩罚（[[6.4-reward hacking]]） | — |
