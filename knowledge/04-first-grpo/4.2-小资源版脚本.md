# 4.2 小资源版脚本逐行讲解（Qwen3-1.7B/4B + LoRA + 4090）

## 一句话
单卡 24GB（4090）跑不动全参训练态（16×1.7≈27GB），所以小资源版用 **LoRA + 更小 batch + offload + 更低 gpu_memory_utilization**，把训练态压到几 GB，让单卡也能跑通 GRPO。

> [!warning] 与集群版的本质区别
> 集群版（[[4.3-集群版脚本]]）是"全参 + 8 卡 FSDP"；小资源版是"LoRA + 单卡 + 强省显存"。**算法（GRPO）完全一样**，只是显存优化手段不同。先读懂 [[1.6-选模型选显卡实战]] 的决策表再来配这套。

## 核心公式/原理

### 小资源显存回顾（Qwen3-1.7B + LoRA + 1×4090 24GB）
| 项 | 计算 | 占用 |
|---|---|---|
| actor 训练态（LoRA） | 2P(冻结) + 16·P_lora | ≈5 GB |
| rollout（g_util=0.5×24） | 权重+KV | ≤12 GB |
| ref（offload） | 卸 CPU | ≈0 |
| 激活（小 micro + ckpt） | — | ≈4 GB |
| 余量 | — | ≈3 GB |
| **合计** | | **≈24 GB ✅** |

### 完整脚本
保存为 `experiments/run_grpo_qwen3_1.7b_lora.sh`：

```bash
#!/usr/bin/env bash
set -x
TRAIN_FILE=$HOME/data/gsm8k/train.parquet
VAL_FILE=$HOME/data/gsm8k/test.parquet

python3 -m verl.trainer.main_ppo \
    algorithm.adv_estimator=grpo \
    data.train_files=$TRAIN_FILE \
    data.val_files=$VAL_FILE \
    data.train_batch_size=64 \
    data.max_prompt_length=512 \
    data.max_response_length=1024 \
    data.filter_overlong_prompts=True \
    data.truncation='error' \
    actor_rollout_ref.model.path=Qwen/Qwen3-1.7B \
    actor_rollout_ref.model.lora_rank=32 \
    actor_rollout_ref.model.lora_alpha=16 \
    actor_rollout_ref.model.target_modules=all-linear \
    actor_rollout_ref.actor.optim.lr=1e-5 \
    actor_rollout_ref.model.use_remove_padding=True \
    actor_rollout_ref.actor.ppo_mini_batch_size=64 \
    actor_rollout_ref.actor.ppo_micro_batch_size_per_gpu=8 \
    actor_rollout_ref.actor.use_kl_loss=True \
    actor_rollout_ref.actor.kl_loss_coef=0.001 \
    actor_rollout_ref.actor.kl_loss_type=low_var_kl \
    actor_rollout_ref.actor.entropy_coeff=0 \
    actor_rollout_ref.model.enable_gradient_checkpointing=True \
    actor_rollout_ref.rollout.log_prob_micro_batch_size_per_gpu=8 \
    actor_rollout_ref.rollout.tensor_model_parallel_size=1 \
    actor_rollout_ref.rollout.name=vllm \
    actor_rollout_ref.rollout.gpu_memory_utilization=0.5 \
    actor_rollout_ref.rollout.n=4 \
    actor_rollout_ref.ref.log_prob_micro_batch_size_per_gpu=8 \
    actor_rollout_ref.ref.fsdp_config.param_offload=True \
    algorithm.use_kl_in_reward=False \
    trainer.critic_warmup=0 \
    trainer.logger='["console","wandb"]' \
    trainer.project_name='verl_grpo_gsm8k_lora' \
    trainer.experiment_name='qwen3_1.7b_lora_grpo' \
    trainer.n_gpus_per_node=1 \
    trainer.nnodes=1 \
    trainer.save_freq=20 \
    trainer.test_freq=5 \
    trainer.total_epochs=15 $@
```

> [!important] LoRA 三个关键参数
> - `lora_rank=32`：低秩矩阵秩，越大可训参数越多、表达能力越强、显存越高。1.7B 用 32 是甜区。
> - `lora_alpha=16`：缩放系数，LoRA 更新按 `alpha/rank` 缩放（16/32=0.5）。
> - `target_modules=all-linear`：对所有线性层注入 LoRA。
> 显存：LoRA 可训参数仅约全参的 0.5%（≈8M），训练态从 27GB 降到 ≈5GB（[[1.6-选模型选显卡实战]]）。

### 与集群版的逐项差异对照
| 参数 | 集群版(8B) | 小资源版(1.7B) | 为什么改 |
|---|---|---|---|
| 模型 | Qwen3-8B 全参 | Qwen3-1.7B **+LoRA** | 单卡装不下全参训练态 |
| `train_batch_size` | 1024 | 64 | 单卡吞吐小，批小些 |
| `rollout.n` | 5 | 4 | 减总 response 数省显存 |
| `ppo_mini_batch_size` | 256 | 64 | 配合 train_batch=64 |
| `ppo_micro_batch_size_per_gpu` | 32 | 8 | 单卡激活显存有限 |
| `rollout.tensor_model_parallel_size` | 2 | 1 | 单卡无法 TP |
| `rollout.gpu_memory_utilization` | 0.6 | 0.5 | 单卡要同时装训练+推理，压更低 |
| `n_gpus_per_node` | 8 | 1 | 单卡 |
| actor lr | 1e-6 | 1e-5 | LoRA 学习率通常比全参大 |
| actor offload | False | （可选 True） | 显存极限时开 |

> [!tip] 还 OOM 怎么办（按顺序试）
> 1. `ppo_micro_batch_size_per_gpu` 8→4→2（[[3.5-batch体系]]）
> 2. `rollout.gpu_memory_utilization` 0.5→0.4（[[1.5-显存分配精算]]）
> 3. `actor.fsdp_config.param_offload=True` + `optimizer_offload=True`
> 4. `data.max_response_length` 1024→512（省 KV）
> 5. 还装不下 → 换 Qwen3-0.6B，或升 [[4.3-集群版脚本]]
> 详见 [[4.5-OOM排查决策树]]。
