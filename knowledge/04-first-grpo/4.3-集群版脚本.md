# 4.3 集群版脚本逐行讲解（Qwen3-8B 全参 + 8×A100）

## 一句话
这是 verl 官方经典的 Qwen3-8B GRPO GSM8K 配置：8 卡 A100/H100、FSDP 全参训练、vLLM rollout、开 gradient checkpointing + remove_padding + ref offload——下面逐行讲清每个参数为什么在、起什么作用。

## 核心公式/原理

### 完整脚本（已验证可跑通）
保存为 `experiments/run_grpo_qwen3_8b.sh`：

```bash
#!/usr/bin/env bash
set -x
# 数据：先用 experiments/prepare_gsm8k.py 生成
TRAIN_FILE=$HOME/data/gsm8k/train.parquet
VAL_FILE=$HOME/data/gsm8k/test.parquet

python3 -m verl.trainer.main_ppo \
    algorithm.adv_estimator=grpo \
    data.train_files=$TRAIN_FILE \
    data.val_files=$VAL_FILE \
    data.train_batch_size=1024 \
    data.max_prompt_length=512 \
    data.max_response_length=1024 \
    data.filter_overlong_prompts=True \
    data.truncation='error' \
    actor_rollout_ref.model.path=Qwen/Qwen3-8B \
    actor_rollout_ref.actor.optim.lr=1e-6 \
    actor_rollout_ref.model.use_remove_padding=True \
    actor_rollout_ref.actor.ppo_mini_batch_size=256 \
    actor_rollout_ref.actor.ppo_micro_batch_size_per_gpu=32 \
    actor_rollout_ref.actor.use_kl_loss=True \
    actor_rollout_ref.actor.kl_loss_coef=0.001 \
    actor_rollout_ref.actor.kl_loss_type=low_var_kl \
    actor_rollout_ref.actor.entropy_coeff=0 \
    actor_rollout_ref.model.enable_gradient_checkpointing=True \
    actor_rollout_ref.actor.fsdp_config.param_offload=False \
    actor_rollout_ref.actor.fsdp_config.optimizer_offload=False \
    actor_rollout_ref.rollout.log_prob_micro_batch_size_per_gpu=32 \
    actor_rollout_ref.rollout.tensor_model_parallel_size=2 \
    actor_rollout_ref.rollout.name=vllm \
    actor_rollout_ref.rollout.gpu_memory_utilization=0.6 \
    actor_rollout_ref.rollout.n=5 \
    actor_rollout_ref.ref.log_prob_micro_batch_size_per_gpu=32 \
    actor_rollout_ref.ref.fsdp_config.param_offload=True \
    algorithm.use_kl_in_reward=False \
    trainer.critic_warmup=0 \
    trainer.logger='["console","wandb"]' \
    trainer.project_name='verl_grpo_example_gsm8k' \
    trainer.experiment_name='qwen3_8b_function_rm' \
    trainer.n_gpus_per_node=8 \
    trainer.nnodes=1 \
    trainer.save_freq=20 \
    trainer.test_freq=5 \
    trainer.total_epochs=15 $@
```
> 来源：verl 官方 Qwen3-8B GRPO GSM8K 示例（hiyouga 镜像验证可跑通，test 集较 base 提升 2 个点）。逐行注释见下。

### 分段逐行讲解

**(1) 算法与数据**
| 参数 | 值 | 为什么 |
|---|---|---|
| `algorithm.adv_estimator` | `grpo` | 用 GRPO 组内相对优势（[[2.4-优势估计]]），无 critic |
| `data.train_batch_size` | 1024 | 全局 1024 prompt/步；×rollout.n=5 → 5120 response（[[3.5-batch体系]]） |
| `data.max_prompt_length` / `max_response_length` | 512 / 1024 | GSM8K prompt 短、CoT 中等；影响 KV cache 显存 |
| `data.filter_overlong_prompts` + `truncation='error'` | True / error | 超长 prompt 直接过滤，遇截断报错（防静默错） |

**(2) 模型与 actor 训练**
| 参数 | 值 | 为什么 |
|---|---|---|
| `actor_rollout_ref.model.path` | `Qwen/Qwen3-8B` | HF 模型路径 |
| `actor.optim.lr` | 1e-6 | RL 微调学习率极小（比 SFT 小一个量级），防策略突变 |
| `use_remove_padding` | True | 去 padding，省显存提速（[[1.5-显存分配精算]]） |
| `ppo_mini_batch_size` | 256 | 每次 actor 更新用 256 条 response；5120/256=20 个 mini-batch |
| `ppo_micro_batch_size_per_gpu` | 32 | 每卡每次反向 32 条；256/8卡=32，恰好整除 |
| `enable_gradient_checkpointing` | True | 重算换显存，让 micro=32 装得下（[[1.5-显存分配精算]]） |

**(3) KL 与 entropy（对应 [[2.3-KL正则]]）**
| 参数 | 值 | 为什么 |
|---|---|---|
| `use_kl_loss` | True | KL 作 loss 项（GRPO 标准做法） |
| `kl_loss_coef` | 0.001 | KL 正则系数，防跑偏 |
| `kl_loss_type` | low_var_kl | k3 低方差无偏估计器 |
| `entropy_coeff` | 0 | 不额外加熵奖励（GRPO 默认） |
| `algorithm.use_kl_in_reward` | False | KL 不进 reward（与 use_kl_loss 互斥） |

**(4) FSDP offload（8B 在 80GB 上的关键）**
| 参数 | 值 | 为什么 |
|---|---|---|
| `actor.fsdp_config.param_offload` | False | 显存够，不卸参数求速度 |
| `actor.fsdp_config.optimizer_offload` | False | 同上 |
| `ref.fsdp_config.param_offload` | True | **ref 用得少，卸到 CPU 省 16GB**（[[1.5-显存分配精算]]） |

**(5) Rollout（vLLM）**
| 参数 | 值 | 为什么 |
|---|---|---|
| `rollout.name` | vllm | 用 vLLM 采样 |
| `rollout.tensor_model_parallel_size` | 2 | vLLM TP=2，8 卡→4 个 vLLM 副本（DP 更高吞吐） |
| `rollout.gpu_memory_utilization` | 0.6 | vLLM 用单卡 60% 显存装权重+KV（0.5–0.7 平衡区） |
| `rollout.n` | 5 | 每 prompt 采 5 条，构成 GRPO 的"组"（必须 >1） |
| `rollout.log_prob_micro_batch_size_per_gpu` | 32 | 算 log_prob 的每卡 micro |

**(6) 训练器**
| 参数 | 值 | 为什么 |
|---|---|---|
| `trainer.critic_warmup` | 0 | GRPO 无 critic，预热步数为 0 |
| `trainer.logger` | console+wandb | 同时打控制台和 wandb |
| `trainer.n_gpus_per_node` / `nnodes` | 8 / 1 | 单机 8 卡 |
| `save_freq` / `test_freq` | 20 / 5 | 每 20 步存 ckpt、每 5 步评测 |
| `total_epochs` | 15 | 训练 15 个 epoch |

> [!success] 显存对照
> 这套配置正是 [[1.5-显存分配精算]] 那张"8×A100 预算表"的实现：训练态 FSDP/8≈16.4GB + 激活(ckpt)≈8GB + rollout(g_util0.6)≤48GB + ref(offload)≈0 + 余量≈8GB ≈ 80GB，刚好不 OOM。改任何一个开关都要重新核对这张表。
