# 3.4 数据流转全链路：prompt → rollout → log_prob → ref → reward → advantage → update

## 一句话
一个 GRPO step 就是 DataProto 在多个 Worker 间"旅行并不断被填充字段"的过程：每经过一个 Worker，就往 `batch` 里 union 进新的张量，最后带着全部字段去做 actor 更新。

## 核心公式/原理

### 全链路七步（GRPO，无 critic）
```
[输入] parquet → 初始 DataProto {prompts, input_ids, attention_mask, data_source, ground_truth}
   │
   ▼ ① generate_sequences (vLLM Rollout Worker)
   │    每个 prompt 采 n 条 → batch ×n
   │    填充: responses, position_ids, (扩展 input_ids/attention_mask)
   ▼ ② compute_log_prob (Actor Worker, 推理模式)
   │    用"采样时"的 actor 算 → 填充: old_log_probs
   ▼ ③ compute_ref_log_prob (Ref Worker)
   │    用冻结参考模型算 → 填充: ref_log_prob
   ▼ ④ compute_scores / reward_fn (Reward)
   │    按 data_source 路由打分 → 填充: token_level_rewards / rm_scores
   ▼ ⑤ compute_advantages (控制进程本地)
   │    组内 z-score → 填充: advantages, returns
   ▼ ⑥ update_actor (Actor Worker, 训练模式)
   │    重算 cur log_prob → ratio → clip+KL loss → backward + step
   ▼
[输出] 更新后的 actor 权重（+ 下一步 rollout 用新权重）
```

> [!important] DataProto 是"只增不减"的
> 每一步用 `output = output.union(new_fields)` 把新字段合并进去，从不删除。所以到 ⑥ 时，一个 DataProto 里同时有 responses、old_log_probs、ref_log_prob、advantages——这正是 [[2.5-GRPO目标函数推导]] 需要的全部原料。
> 来源：verl HybridFlow Guide 主循环。

### 每一步的张量形状变化（以具体数字为例）
设 `train_batch_size=1024`（prompt 数）、`rollout.n=5`、`max_response_length=1024`：

| 步骤 | 关键字段 | 序列数 B | 说明 |
|---|---|---|---|
| 输入 | prompts | 1024 | 每 prompt 一条 |
| ① rollout | responses | **5120** | 1024 × 5（n=5） |
| ② log_prob | old_log_probs | 5120 | 每条 response 逐 token |
| ③ ref | ref_log_prob | 5120 | 同上 |
| ④ reward | token_level_rewards | 5120 | 每条一个标量（放末尾 token） |
| ⑤ advantage | advantages | 5120 | 组内 5 条归一，同组 5 条相同 |
| ⑥ update | （重算 cur log_prob） | 5120 | 分 mini/micro batch 反向 |

> 总序列数 = `train_batch_size × rollout.n`。这是理解 [[3.5-batch体系]] 整除约束的基础。

### 三种 log 概率别混淆
| 字段 | 谁算的 | 何时冻结 | 用途 |
|---|---|---|---|
| `old_log_probs` | actor（采样时快照） | rollout 那一刻 | ratio 的**分母**（行为策略） |
| `cur log_prob`（update 时重算） | actor（当前训练态） | 不冻结，带梯度 | ratio 的**分子**（目标策略） |
| `ref_log_prob` | 参考模型 | 始终冻结 | KL 正则（$\log\pi_\theta - \log\pi_{ref}$） |

> [!warning] 为什么 old 和 cur 要分开
> ratio = `exp(cur_log_prob - old_log_probs)`（[[2.2-重要性采样与PPO-clip]]）。old 是采样那一瞬间的策略（保证重要性采样正确），cur 是训练中被反复更新的策略。PPO 内循环多个 epoch 里，old 不变、cur 一直变，ratio 逐渐偏离 1，被 clip 限制。

### reward 的落点：token_level_rewards
- 规则奖励（GSM8K）只给"整条 response 一个标量分"，verl 把这个分**放到 response 最后一个有效 token**上，其余 token 为 0。
- GRPO 优势是序列级标量（[[2.4-优势估计]]），`compute_advantages` 把它广播到该 response 的每个有效 token（配合 `response_mask`）。

### 权重如何同步回 rollout
⑥ 更新完 actor 后，新权重要传给 rollout 引擎（vLLM）用于下一步采样。actor 与 rollout **colocate 同卡**，通过 NCCL 快速传权重（3D-HybridEngine 的 reshard，详见 [[3.6-3D-HybridEngine]]）。
