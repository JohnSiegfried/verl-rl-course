# 3.2 中间数据格式 DataProto：batch / non_tensor_batch / meta_info

## 一句话
DataProto 是 verl 各 Worker 之间传递数据的统一容器——**张量放 `batch`、字符串/对象放 `non_tensor_batch`、控制信息放 `meta_info`**，理解它就理解了 verl 的数据流。

## 核心公式/原理

### DataProto 的三块结构
定义于 `verl/protocol.py`：

| 字段 | 类型 | 装什么 | 例子 |
|---|---|---|---|
| `batch` | `TensorDict` | 所有**张量**数据（GPU 上） | input_ids、attention_mask、log_prob、advantages |
| `non_tensor_batch` | `dict[str, np.ndarray(object)]` | **非张量**（字符串、dict、对象） | data_source、ground_truth、prompt 文本 |
| `meta_info` | `dict` | **控制/统计**信息，不随样本切分 | temperature、global_stats、timing |

> [!important] 为什么分三块
> - 张量与非张量**切分方式不同**：张量按 batch 维切，字符串不能直接 torch.split。
> - `batch` 可以直接 `.to('cuda')` 整块上卡；`non_tensor_batch` 留在 CPU 用于 reward/日志。
> - `meta_info` 是"全局一份"的信息，不参与 per-sample 切分。

### 关键张量字段（一次 GRPO 训练中会遇到的）
| 字段 | 形状 | 来自哪一步 | 含义 |
|---|---|---|---|
| `input_ids` | `[B, S_prompt+S_resp]` | rollout | prompt+response 的 token id |
| `attention_mask` | `[B, S]` | rollout | 注意力掩码 |
| `position_ids` | `[B, S]` | rollout | 位置 id |
| `responses` | `[B, S_resp]` | rollout | 仅 response 部分 token |
| `prompts` | `[B, S_prompt]` | rollout | 仅 prompt 部分 token |
| `old_log_probs` | `[B, S_resp]` | compute_log_prob | 采样时 actor 的 log π（ratio 的分母） |
| `ref_log_prob` | `[B, S_resp]` | compute_ref_log_prob | 参考模型 log π（KL 用） |
| `token_level_rewards` | `[B, S_resp]` | reward | 逐 token 奖励（通常仅最后一个 token 非零） |
| `advantages` | `[B, S_resp]` | compute_advantages | GRPO 组内优势（同一条内各 token 相同） |
| `response_mask` | `[B, S_resp]` | 数据预处理 | 标记有效 response token（去 padding） |

> 注：`B` = batch 内序列数，`S` = 序列长度。verl 用 `response_mask` 而非 padding 来标记有效位（配合 remove_padding）。
> 来源：verl protocol.py + 数据流各 worker 输出字段。

### 关键非张量字段
| 字段 | 来自 | 含义 |
|---|---|---|
| `data_source` | parquet | 数据集名，用于路由到对应 reward function |
| `reward_model` | parquet | 含 `ground_truth`、`style` |
| `ability` | parquet | 任务类别 |
| `extra_info` | parquet | 样本元信息（split/index） |
| `uid` | rollout | 同组样本标识（GRPO 组内对比用） |

### DataProto 的核心操作
```python
# 合并两个 DataProto 的字段（主循环里反复用）
output = output.union(old_log_prob)

# 按 DP 切分（dispatch 时用）
chunks = data.split(dp_size)

# 拼接（collect 时用）
data = DataProto.concat(chunks)

# 上卡 / 下卡
data = data.to('cuda'); data = data.to('cpu')

# 按字段取子集 / 弹出非张量字段
resp_ids = data.batch['responses']
gt = data.non_tensor_batch['reward_model']
```

> [!tip] 调试 DataProto 的实用技巧
> 想知道某一步数据长什么样，直接在主循环里打印：
> ```python
> print(data.batch.keys())                 # 有哪些张量
> print({k: v.shape for k,v in data.batch.items()})  # 各张量形状
> print(data.non_tensor_batch.keys())      # 非张量字段
> ```
> 这是 [[3.4-数据流转全链路]] 实验 E3 的核心动作。

## 与其他概念的关系
- **前置依赖**：[[3.1-单控制器架构]]（Worker 间靠 DataProto 通信）、PyTorch TensorDict。
- **对比区别**：`batch`（张量，可上卡/切分）vs `non_tensor_batch`（字符串，留 CPU）vs `meta_info`（全局一份）。
- **后续延伸**：[[3.3-输入数据格式]]（parquet 如何变成初始 DataProto）、[[3.4-数据流转全链路]]（DataProto 在各阶段如何被填充）。
