# 3.6 3D-HybridEngine：FSDP ↔ vLLM 权重 reshard 与显存复用

## 一句话
3D-HybridEngine 让同一个 actor 模型在**训练时用 FSDP 切分**、**采样时用 vLLM/Megatron 推理切分**，两种并行布局在同一张卡上通过"权重 reshard + 显存复用"无缝切换——这是 verl 高效且省显存的核心引擎。

## 核心公式/原理

### 要解决的问题
LLM RL 里同一个 actor 要干两件"并行方式矛盾"的事：

| 阶段 | 计算模式 | 最优并行 |
|---|---|---|
| **训练**（update actor） | 大 batch 前向+反向 | **FSDP**（参数/梯度/优化器按 DP 切分） |
| **采样**（rollout 生成） | 自回归逐 token 解码 | **vLLM/Megatron**（TP 切分 + KV cache 管理） |

如果训练一套权重布局、推理另一套，两者**在同一张卡上**就得互相转换，且不能同时占用两份显存——这正是 3D-HybridEngine 解决的。

> [!important] 核心思想
> actor 与 rollout **colocate 在同一张 GPU**（[[3.1-单控制器架构]]）。训练时权重以 FSDP 分片存在；要采样时，把 FSDP 分片 **reshard（重新切分/聚合）** 成 vLLM 需要的 TP 布局，用 NCCL 高效传输；采样完再切回。显存在两种布局间**复用**而非复制。
> 来源：HybridFlow 论文 + verl HybridFlow Guide。

### reshard 的数据流
```
训练态（FSDP 分片权重，按 DP 切）
   │  NCCL all-gather / reshard
   ▼
推理态（vLLM TP 权重 + KV cache）
   │  采样生成 responses
   ▼
（采样结束，释放 KV，权重回 FSDP 布局）
   │
   ▼
回到训练态，继续 update actor
```

### 为什么能省显存
- **不复制权重**：训练和推理共享同一份模型参数，只是布局（分片方式）不同，通过 reshard 就地转换。
- **显存复用**：训练时显存给"参数+梯度+优化器+激活"；采样时这块空间的一部分被复用为"推理权重 + KV cache"。`gpu_memory_utilization` 就是控制 vLLM 在这段复用显存里能占多少（[[1.5-显存分配精算]]）。
- **NCCL 快速传输**：actor/rollout colocate 同卡，权重同步走 NVLink/NCCL，比跨机快得多。

> [!warning] reshard 的代价与调优
> - reshard 有通信开销，rollout.n 越大、模型越大，摊得越薄。
> - `cudagraph_capture_sizes` 的显存**不能 offload**，update actor 时仍占卡，配大易 OOM——见 [[7.1-性能调优]]。
> - 训练与推理引擎版本要对齐（vLLM ≥ 0.8.3），否则 reshard 布局不匹配。

### Hybrid replicas：rollout 与 training 动态切换
verl 进一步支持把同一批 GPU 资源在 Rollout 副本与 Training 副本间**动态扩缩容**：
- 采样阶段：更多 GPU 当 rollout 副本，提吞吐。
- 训练阶段：这些 GPU 切回 training，参与 update。
- 官方实验显示这种动态切换可减少约 **15.3%** 墙钟时间。

> 这是 3D-HybridEngine 思想的延伸：显存与算力在"采样"和"训练"之间按需流转，而不是静态划分。
> 来源：verl 仓库提交记录（Hybrid replicas 动态资源调度实验）。

### 与 Megatron 的关系
- FSDP 方案：训练 FSDP ↔ 推理 vLLM（reshard）。
- Megatron 方案：训练 Megatron(TP/PP) ↔ 推理 Megatron-LM 或 vLLM，权重在 Megatron 布局与推理布局间 reshard。
- 两种方案的控制流（[[3.1-单控制器架构]]）完全一致——这正是单控制器解耦的红利：换后端不改算法。
