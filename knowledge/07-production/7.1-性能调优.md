# 7.1 性能调优全景：rollout 吞吐 + 训练吞吐

## 一句话
RL 训练的时间被切成 rollout（采样）和 update（训练）两段，调优就是分别把这两段的吞吐拉满——rollout 调 vLLM 并发与 KV，update 调 batch 与算子融合，同时用显存技巧换取更大 batch。

## 核心公式/原理

### 先定位瓶颈：看 perf 指标
verl 日志的 `perf/...` 给出各阶段耗时与 tokens/s。一次 step 大致：
```
总时间 = rollout 生成 + log_prob + ref_log_prob + reward + update_actor (+ update_critic)
```
哪段占比最大就调哪段。通常 **rollout 生成是最长的一段**（自回归逐 token），其次是 update。

### A. Rollout 生成吞吐（vLLM）
先开日志看统计：`actor_rollout_ref.rollout.disable_log_stats=False`。

| 手段 | 参数 | 原理 |
|---|---|---|
| 提显存利用 | `gpu_memory_utilization` ↑（0.5–0.7） | 更多权重+KV 上卡（防 OOM 前提下） |
| 提解码并发 | `max_num_seqs` / `max_num_batched_tokens` ↑ | 更多请求同批解码；`max_num_batched_tokens > 2048` |
| 更多副本 | `tensor_model_parallel_size` ↓ | 小 TP→更多 vLLM 副本→DP 吞吐更高（但 KV 更多） |
| CUDA Graph | `cudagraph_capture_sizes` + `enforce_eager=False` | 捕获执行图提速 |

> [!warning] cudagraph 显存不可 offload
> `cudagraph_capture_sizes` 占的显存在 update actor 时**仍在卡上**，配大易 OOM。要小 batch 省显存可略降吞吐。详见 [[1.5-显存分配精算]]、[[3.6-3D-HybridEngine]]。
> 来源：verl Performance Tuning Guide。

> [!note] DP vs TP 的取舍
> HybridFlow 论文 Sec 8.4 评估过：小 TP（更多 DP 副本）吞吐更高，但 KV cache 占用增加。要在"副本数"与"显存"间平衡。
> 来源：verl Performance Tuning Guide。

### B. 训练（update）吞吐
| 手段 | 参数 | 原理 |
|---|---|---|
| 序列打包 | `use_remove_padding=True` | 去 padding，按真实 token 算（llama/mistral/gemma1/qwen 已验证） |
| 动态 batch | `use_dynamic_bsz=True` + `ppo_max_token_len_per_gpu` | 按 token 组 batch，吞吐更高 |
| 算子融合 | LigerKernel | 融合 RMSNorm/SwiGLU/RoPE 等 kernel，省显存提速 |
| 梯度检查点 | `enable_gradient_checkpointing=True` | 省激活→可加大 micro_batch→提吞吐（用时间换空间反过来用） |
| 前向预取 | FSDP `forward_prefetch` | 通信藏在计算下（[[5.2-FSDP原理]]） |
| 激活 offload | `enable_activation_offload=True`（仅 FSDP） | 配 ckpt 省激活，腾给更大 batch |

> [!tip] micro_batch 调优心法（[[3.5-batch体系]] 复习）
> - 开 gradient checkpointing → 把 `ppo_micro_batch_size_per_gpu` 尽量调大到等于归一化后的 mini_batch。
> - forward-only 的（ref/rollout log_prob、critic forward）micro 可设为训练的 **2×**。
> - critic/reward 的 micro 可比 actor 大（actor 末层词表大更吃显存）。

### C. logits/entropy 显存优化
- 算 entropy/log_prob 要对每个 token 输出整个词表 logits（vocab 151936），很吃显存（[[4.5-OOM排查决策树]]）。
- verl 有 "memory optimization for entropy calculation from logits"（chunked 计算），开启后可大幅降低该阶段显存峰值。

### D. 长序列专项
- `ulysses_sequence_parallel_size`：序列并行切激活（[[5.4-verl并行映射]]）。
- FLA（Flash Linear Attention）packed/CP kernel：线性注意力模型的长序列加速。

### 调优顺序（实战）
```
1. 先跑通、不 OOM（[[4.5-OOM排查决策树]]）
2. 开 use_remove_padding + use_dynamic_bsz（低风险高收益）
3. 看 perf 找瓶颈段
4. rollout 慢 → 调 g_util / max_num_batched_tokens / 小 TP
5. update 慢 → 开 ckpt 加大 micro / Liger / 动态 bsz
6. 长序列 → ulysses SP
7. 每改一项实测 perf 对比，别一次改多个
```
