# 7.2 调参经验库：lr / kl_loss_coef / rollout.n / batch / entropy 对策表

## 一句话
把 [[4.4-参数作用精讲]] 的"单参数知识"沉淀成"遇到问题查哪个参数、往哪调"的经验库——这是你在企业里反复用的调参手册雏形。

## 核心公式/原理

### 主参数速查总表
| 参数 | 默认 | 安全区间 | 何时调大 | 何时调小 |
|---|---|---|---|---|
| `actor.optim.lr` | 1e-6 | 1e-7 ~ 1e-5 | 学得太慢、reward 长期不动（先排除其他） | KL 飙升、reward 震荡 |
| `actor.kl_loss_coef` | 0.001 | 1e-4 ~ 1e-2 | 跑偏、hacking、语言退化 | 紧贴 ref 学不动、reward 不涨 |
| `actor.clip_ratio` | 0.2 | 0.1 ~ 0.3 | 收敛太慢（可试 clip-higher） | 更新过猛不稳 |
| `rollout.n` | 4–8 | 2 ~ 16 | 组内对比不足、优势噪声大 | 显存/成本紧 |
| `data.train_batch_size` | 256–1024 | 视显存 | 梯度噪声大、要更稳 | 显存紧、要快迭代 |
| `actor.entropy_coeff` | 0 | 0 ~ 0.01 | 熵坍缩、response 趋同 | 默认一般不动 |
| rollout temperature | ~1.0 | 0.6 ~ 1.2 | 组内太趋同、缺多样性 | 输出质量差、太发散 |
| `kl_loss_type` | low_var_kl | — | — | 一般用 low_var_kl 不动 |

### 场景化对策（症状 → 调参）

**场景 1：reward 一直不涨**
```
排查顺序（先易后难）：
1. 开 num_examine 看 reward 打分是否正确（打分函数写错最常见）
2. 看 rollout dump：模型输出格式对不对（抽不到答案→全 0 分）
3. 查优势是否全 0：GRPO 组内全对/全错 → 调 temperature 增多样性，或换难度适中的数据
4. 查 KL 是否 ≈0 且 lr 太小 → 适当调大 lr
5. 查 kl_loss_coef 是否太大把模型锁死在 ref
```

**场景 2：KL 爆炸 / 策略跑偏**
```
kl_loss_coef ↑（如 0.001→0.005）
lr ↓
确认 kl_loss_type=low_var_kl（k3 最稳）
检查 reward 是否有漏洞导致模型疯狂钻（[[6.4-reward hacking]]）
```

**场景 3：熵坍缩（entropy→0，response 趋同）**
```
用 DAPO clip-higher：提高 clip 上限鼓励探索（[[2.6-算法对比]]）
entropy_coeff 给很小正值（如 0.001）
rollout temperature ↑
检查是否数据太单一/太简单（组内全对，优势全 0 → 用 DAPO dynamic sampling 过滤）
```

**场景 4：response 长度暴涨**
```
加长度惩罚（[[6.2-compute_score接口]] 的 length_penalty）
检查部分分是否按"步骤数"给（鼓励了堆砌）
data.max_response_length 设硬上限
用 DAPO overlong penalty 处理截断逃避
```

**场景 5：训练不稳 / reward 震荡**
```
lr ↓（最常见解法）
train_batch_size ↑（更大 batch 更稳）
确认 grad clip 生效（clip_grad=1.0）
检查数据质量/难度是否忽高忽低
```

**场景 6：LoRA 训不动**
```
lora_rank ↑（16→32→64，表达能力不足）
lora_alpha 配套调（alpha/rank 比例影响更新幅度）
target_modules=all-linear 确认覆盖到位
LoRA lr 可比全参大（1e-5 量级）
```

### 一次只改一个变量（黄金纪律）
> [!important] 调参的科学方法
> 每次实验**只改一个参数**，用 [[6.7-观测与日志]] 的 wandb 多 run 对比，固定 random seed，跑足够步数再下结论。一次改多个参数 = 无法归因 = 纯碰运气。这是企业调参与"炼丹"的本质区别。

### 推荐的第一组扫描实验（新手必做）
固定其他，各扫 3 个值，各跑 200 步，看 reward+val acc+KL：
1. `kl_loss_coef ∈ {1e-4, 1e-3, 1e-2}`（理解 KL 权衡）
2. `lr ∈ {5e-7, 1e-6, 5e-6}`（理解学习率）
3. `rollout.n ∈ {2, 4, 8}`（理解组大小对优势估计的影响）
