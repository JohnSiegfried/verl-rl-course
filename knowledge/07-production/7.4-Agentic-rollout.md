# 7.4 Agentic rollout：多轮工具调用、tool_parser、continuous token（前沿扩展）

## 一句话
verl 不止能训"一问一答"，还支持**多轮智能体 rollout**——模型生成中可调用工具（搜索/代码/计算器），把工具结果拼回继续生成，全程在一个 RL 训练循环里优化——这是 Agent 时代 RL 后训练的前沿。

## 核心公式/原理

### 从单轮到 Agentic 的演进
| 模式 | 生成方式 | reward | 典型 |
|---|---|---|---|
| **单轮** | prompt → 一次性生成 response | 末尾规则分 | GSM8K/MATH（本课程主线） |
| **多轮 Agentic** | 生成→调工具→看结果→再生成…（循环） | 任务完成度 | 搜索 QA、代码 Agent、多步推理 |

> [!note] 为什么 Agentic 是趋势
> 复杂任务（如"查资料再回答""写代码再运行验证"）单轮搞不定，需要模型与外部环境多轮交互。RL 要优化的是**整个多轮轨迹**的最终结果，而不只是单条 response。Qwen3、Kimi、GLM 等都强化了 Agent 能力，verl 的 agentic rollout 正是为这类后训练服务。
> 来源：verl 仓库 agent_loop 提交记录 + Qwen3 博客（Agent 能力）。

### verl 的 Agentic 组件
| 组件 | 路径/机制 | 作用 |
|---|---|---|
| **AgentLoopManager** | `verl/experimental/agent_loop/agent_loop` | 管理多轮 rollout 循环 |
| **tool_agent_loop** | `verl/experimental/agent_loop/tool_agent_loop` | 带工具调用的 agent loop |
| **tool_parser** | `verl/experimental/agent_loop/tool_parser` | 解析模型输出中的工具调用（适配 Qwen/GLM/Kimi/MiniMax 等格式） |
| **Continuous Token** | `verl/utils/continuous_token.py` | 多轮间 token 的连续拼接构建 |

### 多轮 rollout 的数据流（简化）
```
prompt → LLM 生成
   │  tool_parser 检测到工具调用
   ▼
执行工具（搜索/代码/…）→ 得到工具结果
   │  continuous_token 把结果拼回上下文
   ▼
LLM 继续生成（基于更新后的上下文）
   │  （可能再次调工具，循环 N 轮）
   ▼
最终 answer → reward（任务是否完成）→ RL 更新
```

### 训练配置上的差异（相对单轮）
- rollout 用 **async**（vLLM/SGLang async rollout），因为多轮交错、各样本轮数不同。
- reward 常基于**整个轨迹的最终结果**（可能也是规则：答案对/代码通过）。
- 数据格式要支持多轮上下文与工具调用标记。
- 显存/调度更复杂（Continuous Token、动态资源）。

> [!warning] 前沿功能，实验性质
> agentic rollout 在 `verl/experimental/` 下，API 变动快、文档较少。本课只建立概念框架；真要用于生产，需深入对应版本的源码与示例（`examples/sglang_multiturn` 等）。

- 你的任务是**多步推理 / 工具增强 / Agent 场景**（搜索 QA、代码生成+执行、数据分析 Agent）。
- 单轮数学/代码 RLVR 已掌握（Phase 4–6），想拓展到 Agent 后训练。
