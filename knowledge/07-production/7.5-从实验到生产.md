# 7.5 从实验到生产：checkpoint、容错、成本、上线 checklist

## 一句话
实验跑通和能上生产之间隔着"稳定性、可复现、可容错、可估算成本"四道关——本课给一份上线前的完整 checklist，把前六章的知识收拢成可执行的生产标准。

## 核心公式/原理

### 一、Checkpoint 管理
| 项 | 配置/做法 | 说明 |
|---|---|---|
| 保存频率 | `trainer.save_freq=N` | 太频繁占盘，太少丢失多；数学任务 20–50 步 |
| 保留策略 | 定期清理旧 ckpt | 全参 8B 一个 ckpt ≈16GB+，长期训练会爆盘 |
| 最优选择 | 按 **val acc** 选，不是按 reward | reward 可能 hacking（[[6.4-reward hacking]]），val 才是真相 |
| 断点续训 | resume 机制 | 含模型+优化器+步数，恢复后曲线连续 |

> [!warning] 选 checkpoint 用 val 指标
> 这是最容易犯错的地方：按 reward 最高选 ckpt，可能选到 hacking 最严重的那个。**永远按隔离 val 集的 acc/pass@k 选**（[[6.5-评测集构建]]）。

### 二、容错与稳定性
- **单机故障**：checkpoint + resume，定期保存是关键。
- **多机故障**：某节点挂 → Ray 重组；训练中断后从最近 ckpt 恢复（[[5.6-多机多卡]]）。
- **随机性控制**：固定 random seed，记录 git commit / 镜像版本 / 配置快照，保证可复现。
- **长训练监控**：配 [[6.7-观测与日志]] 的告警，异常早发现早停，省算力。

### 三、成本估算（企业必须算清）
$$\text{成本} = \text{卡时} = \frac{\text{总 token}}{\text{吞吐(tokens/s/卡)} \times 3600} \times \text{单卡时价}$$
- **总 token** ≈ train_batch × rollout.n × (prompt+response 长) × 总步数 × ppo_epochs。
- **吞吐** 从 [[7.1-性能调优]] 的 perf 实测（tokens/s/卡）。
- **显存/卡数** 决定用什么卡（[[1.6-选模型选显卡实战]]）→ 决定单卡时价。

> [!tip] 降本三杠杆
> ① 提吞吐（[[7.1-性能调优]]）→ 卡时↓；② 用更小模型/LoRA（[[1.6-选模型选显卡实战]]）→ 单卡价↓；③ Hybrid replicas 动态调度（[[3.6-3D-HybridEngine]]，官方称省约 15.3% 墙钟）→ 卡时↓。

### 四、上线前 Checklist（核心交付）
```
【数据】
□ train/val/test 严格隔离，已去重（含近重复）
□ 数据格式符合五字段，ground_truth 与打分函数对齐
□ 数据难度分布合理（不会全对/全错导致优势全 0）

【Reward】
□ compute_score 经 num_examine 人工核对无误
□ 已加必要的反 hacking（长度/格式/overlong 惩罚）
□ 混合奖励权重合理，单一信号不主导

【训练配置】
□ batch 整除约束满足（train×n % world_size == 0 等）
□ 显存预算表已核算，留 10–20% 余量
□ kl_loss_coef / lr / clip 经扫描实验定值
□ 并行方案匹配硬件（TP 限单机、FSDP/PP 跨机）

【观测】
□ wandb/mlflow 五组面板就位（reward/能力/稳定/行为/性能）
□ rollout dump 开启，定期人工抽查
□ 关键指标告警（val 降、KL 爆、entropy 坍缩、长度异常）

【评估】
□ 评测集独立，指标明确（pass@1/pass@k + temperature + n）
□ base 模型基线已测，提升幅度量化
□ 已确认无 reward hacking（val 与 reward 同向）

【生产】
□ checkpoint 按 val 指标选优，保留策略定好
□ 可复现（seed/commit/镜像/配置快照）
□ 容错（save_freq + resume）
□ 成本已估算，预算内
```
