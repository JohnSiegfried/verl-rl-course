# 6.1 Reward function 设计：rule / model(DisRM/GenRM) / 混合

## 一句话
Reward 是 RL 的唯一监督信号，设计好坏直接决定训练成败；verl 支持**规则奖励**（确定性、免费）、**模型奖励**（DisRM 判别式 / GenRM 生成式）和**混合奖励**，选哪种取决于任务是否"可验证"。

## 核心公式/原理

### 三类 Reward 对比
| 类型 | 原理 | 成本 | 噪声 | 适用 |
|---|---|---|---|---|
| **Rule-based** | 写死的规则（字符串匹配/数学验证/代码跑测试） | 免费 | 低（确定） | 数学/代码/格式（可验证） |
| **DisRM**（判别式 RM） | 训一个打分模型输出标量分 | 高（要训 RM + 推理） | 中 | 开放式偏好（RLHF） |
| **GenRM**（生成式 RM） | 用生成模型"评判"再解析出分 | 高 | 中高 | 复杂推理评判 |
| **Hybrid** | 规则 + 模型组合 | 中 | 中 | 多目标（如格式用规则+质量用 RM） |

### 怎么选（与 [[1.1-RL后训练全景]] RLHF/RLVR 呼应）
```
任务有可验证的标准答案/可执行测试？
├─ 是（数学/代码/格式）→ Rule-based ✅（本课程主线，RLVR）
│     优点：零成本、无 reward hacking 的 RM 漏洞、确定可复现
└─ 否（开放对话/创意/有用性）→ 需要 RM
      ├─ 有偏好标注数据 → DisRM（标量分，高效）
      ├─ 要评判复杂推理 → GenRM（生成式评判）
      └─ 多目标 → Hybrid（规则管格式 + RM 管质量）
```

### Rule-based 奖励设计（数学示例）
GSM8K 的经典三段式打分（verl 预实现）：
```python
# 伪代码逻辑（verl/utils/reward_score/gsm8k.py）
def compute_score(solution_str, ground_truth):
    pred = extract_answer(solution_str)      # 抽 #### 后的答案
    if pred is None:
        return 0.0                            # 格式错误 → 0 分
    if is_equiv(pred, ground_truth):
        return 1.0                            # 完全正确 → 1 分
    else:
        return 0.1                            # 格式对但答案错 → 0.1 分（鼓励格式）
```

> [!important] 部分分（partial credit）的设计哲学
> 给"格式对但答案错"0.1 分而非 0 分，是为了**鼓励模型先学会输出格式**，再学会算对。这是 reward shaping 的基本功：把"最终目标"拆成"可达成的中间台阶"。但要小心部分分被模型钻空子（[[6.4-reward hacking]]）。

### Model-based 奖励（DisRM/GenRM）
- **DisRM**：输入 (prompt, response)，RM 输出一个标量 reward。verl 支持如 `Skywork-Reward-Llama-3.1-8B`。
  - 只占最后一个 token 的 hidden → 打分头 → 标量。
- **GenRM**：用一个生成模型（如 `FAPO-GenRM-4B`）生成"评判文本"，再从中解析出分数。
  - 能给出评判理由，适合复杂推理，但更贵更慢。

> [!warning] RM 的两个固有风险
> 1. **reward hacking**：模型学会"讨好 RM 的偏好"而非真正变好（RM 本身是近似）。
> 2. **OOD 失效**：RM 在训练分布外的 response 上打分不准。
> → 这就是为什么数学/代码优先用 rule-based（无 RM 可 hack）。详见 [[6.4-reward hacking]]。

### 混合奖励（Hybrid）
把多个奖励加权组合：
$$r_{total} = w_1 \cdot r_{rule} + w_2 \cdot r_{RM} + w_3 \cdot r_{format} + \dots$$
- 例：数学任务 = 0.9×答案对错(rule) + 0.1×长度适中(format)。
- verl 的 RewardLoop 支持 hybrid 配置（rule + GenRM 等，[[6.3-RewardManager]]）。

### verl 中配置 rule vs RM
```bash
# 规则奖励：不需要 reward 模型，reward_fn 按 data_source 路由
# （parquet 的 reward_model.style='rule' + ground_truth）

# 模型奖励：指定 RM 路径
reward_model.enable=True
reward_model.model.path=Skywork/Skywork-Reward-Llama-3.1-8B-v0.2

# 自定义 reward 函数（最灵活）
reward_model.custom_reward_function.path=/path/to/my_reward.py
reward_model.custom_reward_function.name=compute_score
```
