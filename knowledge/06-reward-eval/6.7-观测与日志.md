# 6.7 观测与日志：console / wandb / mlflow、rollout dump、告警

## 一句话
看不见就调不动——用 wandb/mlflow 记录 [[6.6-指标与评估体系]] 的曲线，用 rollout dump 把模型真实输出存下来人工抽查，再配关键指标告警，构成完整的训练观测体系。

## 核心公式/原理

### 配置日志后端
```bash
trainer.logger='["console","wandb"]'        # 控制台 + wandb
# 或 '["console","mlflow"]' / 三者组合
trainer.project_name='verl_grpo_gsm8k'      # wandb/mlflow 项目名
trainer.experiment_name='qwen3_8b_grpo'     # 实验名（一次训练一个）
```
- **console**：实时打印，调试期看。
- **wandb**：曲线面板、对比多实验、团队共享（推荐）。
- **mlflow**：自建/私有化部署时用。

### 必看的几组面板（wandb 建议布局）
| 面板 | 指标 | 看什么 |
|---|---|---|
| Reward | `critic/score/mean` | 是否总体上升 |
| 能力 | `val/acc`、`val/pass@k` | 是否真变好（最重要） |
| 稳定 | `actor/kl_loss`、`actor/entropy`、`actor/grad_norm` | 是否稳/熵坍缩 |
| 行为 | `response_length/mean` | 是否长度 hacking |
| 性能 | `perf/tokens_per_sec`、各阶段耗时 | 瓶颈在哪（[[7.1-性能调优]]） |

> [!tip] 多实验对比
> wandb 按 `experiment_name` 分组，把不同 `kl_loss_coef`、`lr`、算法的 run 叠在一起看——这是 [[7.2-调参经验库]] 的核心动作。

### rollout dump：把模型输出存下来
曲线是"数字"，但模型具体输出了什么要**亲眼看**。rollout dump 把 response 落盘：
```yaml
trainer.rollout_data_dir: ./rollout_dump   # 存训练中的 rollout
trainer.val_data_dir: ./val_dump           # 存验证时的生成
```
- 存成 parquet/jsonl，含 prompt / response / reward。
- **定期人工抽查**：看模型是真的在推理，还是在堆格式/复读——这是发现 reward hacking 最直接的方式，曲线看不出来。

> [!warning] 别只看曲线不看文本
> 很多训练事故（格式错误、复读机、答非所问）曲线正常但输出已崩。每次 save_freq 抽 5–10 条 rollout 读一遍，是性价比最高的"人肉评估"。

### 告警（关键指标越界通知）
- wandb 支持对指标设阈值告警（如 `val/acc` 下降、`actor/kl_loss` 飙升时发邮件/Slack）。
- 自建 mlflow 可配简单脚本轮询指标，越界则通知。
- 告警项建议（对应 [[6.6-指标与评估体系]] 诊断表）：val acc 下降、KL 突增、entropy 坍缩、response 长度暴涨。

### 断点续训与观测连续性
- `trainer.save_freq` 存 checkpoint，配合 resume 机制，长训练中断后曲线能接上。
- checkpoint 里含模型 + 优化器状态 + 步数，恢复后 wandb 曲线连续。
