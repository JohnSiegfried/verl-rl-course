# 6.5 评测集构建：划分、防泄漏、pass@k / avg@k / best@k

## 一句话
评测集是判断"模型是否真的变好"的唯一标尺——必须**与训练集严格隔离、分布代表真实场景、指标选 pass@k/avg@k**，否则 reward 涨了也可能是自欺欺人（含 [[6.4-reward hacking]]）。

## 核心公式/原理

### 三层数据划分
| 集合 | 用途 | 能否进训练 |
|---|---|---|
| **train** | RL 训练的 prompt | ✅ |
| **val**（验证） | 训练中定期评估（`test_freq`）、调参/早停依据 | ❌ |
| **test**（测试） | 最终一次性评估，报告用 | ❌❌（碰都不能碰） |

> [!warning] val 和 test 分开
> 用 val 调参/选 checkpoint 会"过拟合到 val"。所以最终报告要用一个**全程没参与任何决策**的 test 集。verl 的 `data.val_files` 是 val；test 需你自己留。

### 防数据泄漏（企业最容易踩的坑）
- **去重**：train 与 val/test 之间做 prompt 级去重（含近重复——换几个数字的"孪生题"也要去）。
- **源头隔离**：评测用公认 benchmark（GSM8K test、MATH test、AIME）时，确认 train 集没混入这些 benchmark 的题目。
- **时间隔离**：新出的 benchmark（防训练数据污染）更有说服力。

> [!danger] 泄漏的后果
> train 里混进 val/test 的题 → val acc 虚高 → 你以为模型变强了，实际只是"背过答案"。这在 RL 里更隐蔽，因为 RL 会反复采样 train prompt，泄漏的题 reward 天然高。

### 评测指标：pass@k / avg@k / best@k
对同一 prompt 采样 $n$ 个 response，如何衡量能力？

| 指标 | 定义 | 含义 | 适用 |
|---|---|---|---|
| **pass@1** | 单次采样的正确率（期望） | 平均能力 | 线上服务（一次一答） |
| **pass@k** | $n$ 次采样中**至少 1 次**对的概率 | 探索上限 | 允许重试/投票 |
| **avg@k** | $n$ 次采样的**平均**正确率 | 稳定性 | 综合 |
| **best@k / maj@k** | 多数投票/最优 | 集成能力 | 自一致性 |

**pass@k 的无偏估计**（$n$ 次采样中 $c$ 次正确）：
$$\text{pass@k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}$$

> [!important] 选哪个指标看应用场景
> - **To-C 聊天**（一次一答）→ pass@1 / avg@k。
> - **可重试/可验证**（数学解题、代码可跑测试）→ pass@k（只要对一次就算解决）。
> - **自一致性**（采多条投票）→ maj@k。
> RL（尤其 GRPO，rollout.n>1）天然适合报 pass@k——因为它本来就在练"组内至少一个好"。

### 评测的采样设置（影响结果可比性）
- **temperature**：评测常用 0（贪心，可复现）或与训练一致的采样温度。报指标时必须注明。
- **n（采样数）**：pass@k 需 n≥k。
- **max_response_length**：评测要给够长度，否则截断误判错。
- **chat_template**：与训练一致（含是否 thinking 模式）。

### verl 中的评测
- `data.val_files` + `trainer.test_freq=N`：每 N 步在 val 上测一次。
- 评测用 rollout 引擎生成 → reward function 打分 → 统计 acc/pass@k。
- 日志里 `val/...` 前缀的指标（[[6.6-指标与评估体系]]）。

### 构建企业自定义评测集的清单
```
① 从真实业务场景采样 prompt（覆盖主要任务类型）
② 严格去重（vs train，含近重复）
③ 每个 prompt 标注可靠 ground_truth / 评分标准
④ 划分 val（调参用）+ test（报告用），比例如 1:1 或全留 test
⑤ 定指标：pass@1 / pass@k / avg@k（注明 temperature、n、k）
⑥ 建立 base 模型基线（对比提升）
⑦ 定期用新数据刷新，防过拟合到旧评测集
```
