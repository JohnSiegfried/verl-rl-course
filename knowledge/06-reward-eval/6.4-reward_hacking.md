# 6.4 reward hacking 与缓解：长度 / 格式 / overlong 惩罚 + KL

## 一句话
模型会"钻 reward 的空子"拿高分而非真正变好——比如无脑拉长、堆格式、讨好 RM；缓解靠**精心的 reward shaping（长度/格式/overlong 惩罚）+ KL 约束 + 监控异常指标**。

## 核心公式/原理

### 什么是 reward hacking
策略优化的目标是最大化 reward，但 reward 只是"真实目标"的近似。当模型找到 reward 函数没覆盖的"捷径"，就会出现 reward 升高但实际能力不变甚至下降——这就是 reward hacking（ reward 被"黑"了）。

> [!warning] 典型 hacking 模式（数学/代码 RLVR）
> | hacking | 表现 | 根因 |
> |---|---|---|
> | **长度膨胀** | response 越写越长，塞无关内容 |  reward 与"看起来更努力"相关；或部分分按步给 |
> | **格式堆砌** | 反复输出 ####、重复答案 | 格式分被过度奖励 |
> | **答案复诵** | 抄 prompt 里的数字当答案 | 抽取逻辑太宽 |
> | **截断逃避** | 故意写到超长被截断，躲避"答错"判定 | 截断=0 分变成可钻的空子 |
> | **RM 讨好**（RLHF） | 生成 RM 偏爱但无用的套话 | RM 本身是近似 |

### 缓解 1：长度惩罚
防止无脑拉长。两种形式：
- **硬上限**：`data.max_response_length` 截断（必要但不充分，模型仍会顶到上限）。
- **软惩罚**：reward 里对超长扣分（见 [[6.2-compute_score接口]] 的 `compute_score_with_length_penalty`）：
$$r = r_{base} - \lambda \cdot \max(0, \text{len} - L_{max}) / L_{max}$$

> [!tip] 监控长度曲线
> response 平均长度是重要的"健康指标"。正常情况下它会随能力上升而**适度**变化；若**持续暴涨**而 acc 不涨，多半是长度 hacking。见 [[6.6-指标与评估体系]]。

### 缓解 2：格式惩罚/约束
- 格式分**只给小额部分分**（如 0.1），别让格式分盖过正确性分。
- 答案抽取要**严格**（只认 `####` 后第一个数字），防"多写几个 #### 碰运气"。

### 缓解 3：Overlong Reward Shaping（DAPO 的解法）
模型故意写到超长被截断来逃避"答错得 0 分"——DAPO 的 **overlong penalty** 给"超长被截断"一个**软惩罚而非硬 0 分**：
- 做法：对超过某长度阈值的 response，给一个随长度渐增的负分（而非直接 0）。
- 效果：消除"截断比答错更划算"的扭曲激励，减少奖励噪声。
- verl：用 `dapo` reward manager（[[6.3-RewardManager]]）。
> 来源：DAPO 论文（Overlong Reward Shaping）。

### 缓解 4：KL 约束（[[2.3-KL正则]]）
KL 正则把策略锚在参考模型附近，**限制模型为追 reward 而剧烈偏离正常语言分布**：
$$r \to r - \beta\,\mathbb{D}_{KL}(\pi_\theta \| \pi_{ref})$$
- β 太小 → hacking 风险大；β 太大 → 学不动。观测 KL 曲线缓慢上升为佳。
- 这是"防 reward 把模型练飞"的最后一道闸。

### 缓解 5：监控与早停（[[6.6-指标与评估体系]]）
建立"reward 升但实际指标不涨"的告警：
| 信号 | 可能的 hacking |
|---|---|
| reward↑ 但 val acc 平/降 | 找到 reward 漏洞 |
| response 长度持续暴涨 | 长度 hacking |
| KL 突然飙升 | 策略突变/跑偏 |
| entropy 坍缩到很低 | 失去多样性，可能钻单一模式 |

### 一个综合的抗 hacking reward 设计模板
```python
def compute_score(data_source, solution_str, ground_truth, extra_info=None):
    # ① 正确性（主信号，权重最大）
    correct = check_correct(solution_str, ground_truth)
    score = 1.0 if correct else 0.0
    # ② 格式分（小额，仅鼓励，不主导）
    if not correct and has_valid_format(solution_str):
        score = 0.1
    # ③ 长度软惩罚（防膨胀）
    score -= length_penalty(solution_str, max_len=1024)
    # ④ overlong 软惩罚（防截断逃避，DAPO 式）
    if is_truncated(solution_str):
        score = overlong_penalty(solution_str)   # 非 0，而是渐增负分
    return {"score": score, "acc": int(correct)}
```
> 配合训练端 `kl_loss_coef` 与长度/KL/entropy 监控，形成"reward shaping + KL + 监控"的三层防御。
